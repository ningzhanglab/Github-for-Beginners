A REAL-LIFE EXAMPLE

You're writing a small economics paper.

You write the first draft. A classmate edits a paragraph. An AI assistant suggests a clearer definition for an unemployment-rate variable. GitHub helps you see who changed what and whether to keep that change.

Remember one idea: GitHub helps you review how a project changes. Start with one small text file; you can learn the extra features later.
When should you NOT use GitHub? Google Docs is often easier for simultaneous Word-style editing. GitHub is especially helpful for text files, project history, documentation, scripts, and controlled collaboration. Don't put private research data in a public repository.

✦ LESSON 04 · WORKING WITH OTHERS

A change doesn't have to go straight into main.

Main is usually the accepted version of your project. Click through four steps to see how a classmate can safely suggest an improvement.

💡
You remain in control. Issue = task; Branch = separate workspace; Pull Request = ask for review; Merge = accept a change.

✦ LESSON 05 · AI AS A CONTRIBUTOR

Let AI help. You still approve.

AI can draft explanations and propose file changes. The important part is making the task small and checking what it changed.

Where is your AI assistant working?

A COPY-READY AGENT INSTRUCTION
Explain the columns in my sample economics dataset. Only edit the data dictionary on a separate branch. Do not change the CSV, publish secrets, or merge anything. Report the files changed and what you checked. If you cannot edit the repository, return a draft instead.
💡
Before accepting AI work: Compare the actual files and lines changed. A completion message alone isn't proof.
A TINY INTERACTIVE REVIEW EXERCISE

An agent says “Done.” What should you do?

It was asked to explain the dataset columns. Examine the *actual proposed file changes* below. Would you accept this work?
